# ADR-004: Where each decision is made

- Status: Proposed
- Date: 21 September 2026
- Related: ADR-003 (which named the substrates), `docs/gates.md`, `docs/tiers.md`
- Scope: Every point in MIMIR where something is chosen

---

## 1. The problem, measured

ADR-003 said MIMIR should coordinate several computational substrates rather
than treat the language model as the whole reasoning system. It named the
substrates. It did not say which decisions go to which, and in practice
almost all of them stayed with the generative model.

Four measurements say that is the live defect.

**One.** Sixteen of nineteen corpus failures on qwen3-coder:30b were a
specialist that never concluded. The decision "should I call another tool or
answer now" was never made anywhere. It was an emergent property of whether
the model happened to stop emitting tool calls before a budget ran out. The
fix was a loop restructure, not a model.

**Two.** Pair consistency sits at 0.40 to 0.47 across 7B, 30B and 117B. The
contrastive pairs ask whether the answer changes when one fact changes, which
is discrimination, and scale does not move it. A seventeen-fold parameter
increase bought two model cases out of fifty-eight.

**Three.** The four deterministic gates built to fix specific discrimination
failures made the score worse, and one of the two causes was a regex deciding
whether a search had failed. It could not tell a runbook that discusses
timeouts from a report that one occurred. The judgement was right to make;
the mechanism was wrong for it.

**Four.** The decision layer that would have made that judgement properly has
existed for some time, tested, wired into one call site, with its backend
disabled and nothing listening on its port.

## 2. Decision

Every decision point in MIMIR is assigned to one of three mechanisms, by the
shape of the decision rather than by which component happens to be nearby.

### Tier 1: structural. Plain code.

For anything that is arithmetic, a lookup, or a property of a data structure.

- Is this listing empty: a length.
- Is this note older than the freshness window: a subtraction.
- Do these retry gaps double: a ratio over timestamps.
- Is this definition ever read: an AST walk.
- Did this command exit non-zero: a field.
- Is this tool budget spent: a comparison.

A model here is strictly worse. It is slower, it disagrees with itself
between runs, and the right answer is computable. **Safety decisions live
here permanently**, whatever accuracy a classifier reaches, because a safety
property must not depend on a probability.

### Tier 2: discriminative. A closed-set decision model.

For a bounded judgement over text, where the answer set is small and known
in advance, and where a tier-1 rule has been tried and proved brittle.

- Did this search fail, return empty, or return data.
- Which of these candidate workloads did the operator mean.
- Is the evidence gathered sufficient to answer the question asked.
- Do these two specialist reports actually conflict.

The qualifier matters and is the whole guard against this tier eating the
system. A rule that is right every time it has been measured is not replaced
by a classifier that is right ninety percent of the time, however good the
classifier. The retrieval-outcome regex earned its way here by failing on a
real run, not by looking hard.

### Tier 3: generative. The language model.

For open-ended output: the answer prose, the plan, the hypothesis, the
explanation.

**The rule that follows from this:** a generative model is never asked a
question whose answer set is small and known. If the answer is one of three
things, the question belongs in tier 1 or tier 2.

## 3. What does not move

Stated explicitly so this ADR cannot be read as "use the decider everywhere".

- **Risk classification** stays deterministic. Safety must not depend on a
  probability.
- **Triage routing** stays a rule. It has been right every time it has been
  measured.
- **Tool choice** stays with constrained decoding, which measures 100%
  adherence at every model size tested here. There is nothing to improve.
- **Staleness, empty listings, gap doubling, dead definitions** stay in tier
  1. They are arithmetic and the gates that compute them work.

## 4. Consequences

The decision layer needs a backend that exists. `LocalDecider` constrains the
already-loaded generative model to the option set by JSON schema and
implements the same protocol, so call sites swap to Kev by changing config.
It gives the closed set today and not the calibration, and says so through
`Verdict.calibrated` rather than by reporting a number that means nothing.

Standing up Kev remains worth doing and is now an upgrade rather than a
prerequisite: same call sites, same protocol, better scores and far cheaper
per decision.

Each decision point moves one at a time, with the corpus re-measured after
each. The four gates were built together and shipped together, and when the
number went down it took a session to find which of them had done it.

## 5. Status of the migration

| decision | today | target | moved |
|---|---|---|---|
| continue gathering or conclude | emergent from the loop | tier 1 | yes, `_conclude` |
| retrieval outcome | tier 1 regex, brittle | tier 2 | pending |
| target selection | generative | tier 2 | pending |
| evidence sufficiency | generative | tier 2 | pending |
| report conflict | generative (`verify` node) | tier 2 | pending |
| risk class | tier 1 | tier 1 | stays |
| triage route | tier 1 | tier 1 | stays |
| tool choice | constrained generative | unchanged | stays |
| answer prose | tier 3 | tier 3 | stays |
