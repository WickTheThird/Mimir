- Scope: Investigation, software engineering, operational reasoning, memory,

## 1. Decision

MIMIR will evolve from a single-pass LLM-agent pipeline into a recurrent,
model-independent cognitive architecture.

The system will no longer treat the language model as the complete reasoning
system. Instead it will use a shared cognitive state and coordinate multiple
computational substrates: language models, structured world models, causal
hypothesis models, graph algorithms, symbolic solvers, statistical models,
code-analysis engines, deterministic critics, sandbox execution, learned
transition models, and eventually continuous-time or event-driven models.

The LLM remains responsible for natural-language understanding, semantic
abstraction, hypothesis generation, code proposals and explanation. It does not
own durable truth, safety, exact computation, persistent state, stopping
decisions or final authority over actions.

The central intelligence of MIMIR resides in the closed loop:

```
observe
  -> update beliefs
  -> generate or revise hypotheses
  -> predict
  -> choose an action
  -> execute
  -> compare prediction with reality
  -> verify
  -> learn
  -> continue or stop
```

All reasoning systems communicate through a typed, model-independent cognitive
representation. The architecture is introduced incrementally. No learned model
or new reasoning substrate is trusted merely because it is theoretically
promising. Every component must outperform or complement the current baseline
under controlled evaluation.

## 2. Context

MIMIR currently contains approximately 36,000 lines across 17 packages. Its
graph is a single-pass pipeline:

```
START -> resolve_context -> recall_memory -> coordinate -> [ask_user]
      -> select_skills -> specialist x N -> gather -> [verify]
      -> safety_review -> synthesise -> curate_memory -> finalise -> END
```

There is no back edge. Although `max_specialist_rounds` exists in
configuration, execution does not return to coordination, action selection or
specialist routing after observing results. The system plans once, acts once
and answers once.

Proven strengths: 65 typed tools, capability-tagged tool access, deterministic
risk classification, model-independent approval policy, persistent evidence and
execution records, run provenance, reproducible evaluation, claim-support
verification, zero unapproved mutations in measured evaluation, stable
deterministic policy behaviour across model sizes.

Measured weaknesses: compute changes little with task difficulty; failed cases
consume disproportionately more tools; failed cases produce less usable
evidence; context grows substantially during sessions; specialist routing is
insufficiently sparse; unsuccessful runs repeat work without measurable
progress; evidence is stored but not assembled into a persistent model of the
investigated system; specialists exchange prose rather than structured beliefs;
the sandbox exists but is not a standard simulation mechanism.

These failures are not solvable through prompt tuning. They result from missing
architectural capabilities: recurrence, structured cognitive state, explicit
uncertainty, prediction, hypothesis competition, causal reasoning, progress
measurement, heterogeneous reasoning, bounded working memory, and
model-independent stopping.

## 3. Problem statement

MIMIR must investigate and act on complex software systems while maintaining
evidence-backed conclusions, deterministic safety, bounded resource use,
reproducibility, explicit uncertainty, correction after failed predictions,
persistent system understanding, correct reasoning-method selection, safe
degradation when models fail, and measurable improvement over time.

A system composed only of LLM prompts and tool calls does not satisfy these
requirements. Language models are useful for interpretation, abstraction and
generation, but unreliable as the sole mechanism for exact graph traversal,
arithmetic, constraint satisfaction, persistent state, temporal dynamics,
causal validation, deterministic policy, calibrated uncertainty, execution
verification and long-lived memory.

The architecture must separate language intelligence from system cognition.

## 4. Design principles

### 4.1 The LLM is a component, not the brain

**Used for:** understanding requests, translating natural language into
structured goals, generating candidate hypotheses, resolving semantic
ambiguity, proposing code, interpreting unfamiliar evidence, summarising
verified conclusions, explaining trade-offs.

**Not authoritative for:** truth, permissions, risk classification, exact
calculations, state persistence, evidence validity, action approval, stopping,
policy enforcement.

### 4.2 Reality outranks model output

```
direct execution or observation
  > deterministic derivation
  > verified structured evidence
  > validated memory
  > model prediction
  > model-generated narrative
```

A model assertion conflicting with observed reality must be rejected or marked
contradicted.

### 4.3 State must survive model replacement

Changing the model, its quantisation, context size or prompt must not erase the
investigation. Durable intelligence lives in typed observations, entities and
relations, hypotheses, predictions, actions and outcomes, evidence, memory,
policies and verified artifacts. Not in conversation history.

### 4.4 Every action must have a reason

Before executing, MIMIR records which goal it advances, which hypothesis it
tests, what outcome is expected, what information may be gained, its estimated
cost, its risk, and why it is preferred over alternatives.

An action without a measurable purpose is not reasoning. It is merely activity
wearing a serious expression.

### 4.5 Every significant prediction must be checked

Actions produce a prediction before execution where possible. Afterwards MIMIR
compares predicted with actual observation. The difference is a prediction
residual and must affect belief state.

### 4.6 Safety remains immutable

The following may not become learned, model-controlled or mutable through the
AI Gene: risk boundaries, approval requirements, credential restrictions,
production mutation policy, evidence requirements for sensitive actions,
external-network restrictions, provenance requirements, sandbox containment,
user authority.

Safety may be improved through code changes and review, but not automatically
evolved.

### 4.7 Deterministic mechanisms take precedence for formal tasks

Graph traversal, arithmetic, sorting, filtering, dependency resolution, AST
inspection, schema validation, policy evaluation, timeline construction,
constraint checking, test execution.

### 4.8 Learned components earn admission

A new learned model must demonstrate a measurable advantage: higher task
success, better calibration, fewer tool calls, lower latency, lower memory,
better prediction, better anomaly detection, improved generalisation or
robustness. Novelty is not an architectural requirement.

## 7. Cognitive state

At step `t`, state is `S_t = (G_t, W_t, H_t, B_t, M_t, Q_t, A_t, C_t)` where
`G` is the active goal set, `W` the bounded workspace, `H` the hypothesis set,
`B` the belief distribution, `M` relevant durable memory, `Q` unresolved
questions, `A` candidate actions, `C` remaining resource and safety
constraints.

An executed action `a_t` yields observations `o_{t+1} ~ P(o | S_t, a_t)`, and
the transition is `S_{t+1} = T(S_t, a_t, o_{t+1})`.

Initially `T` is implemented through deterministic update rules plus
constrained model proposals. Later a learned model may estimate parts of
`T_theta(S_t, a_t) -> S_hat_{t+1}`. The learned transition model predicts state
changes but never directly overwrites observed reality.

## 8. Bounded workspace

Default capacity: one active primary goal, up to three active hypotheses, up to
eight critical observations, up to five unresolved questions, up to five
candidate actions, up to five active constraints, evidence references rather
than payloads, current budget and stopping state.

```python
@dataclass
class Workspace:
    primary_goal_id: str
    active_hypothesis_ids: list[str]
    critical_observation_ids: list[str]
    unresolved_question_ids: list[str]
    candidate_action_ids: list[str]
    active_constraint_ids: list[str]
    remaining_budget: Budget
```

Admission considers goal relevance, evidential strength, freshness,
contradiction importance, expected impact on action selection, uniqueness and
recency. The workspace manager enforces limits deterministically. The LLM may
recommend additions or removals but may not bypass capacity or provenance
rules.

## 9. Recurrent investigation loop

```
resolve goal
  -> load workspace and world state
  -> generate or revise hypotheses
  -> generate candidate actions
  -> rank actions
  -> policy check
  -> execute selected action
  -> ingest observations
  -> compare prediction with outcome
  -> update beliefs and world state
  -> run critics
  -> stop, ask, replan or continue
```

```python
def route_after_transition(state: CognitiveState) -> NextNode:
    if state.policy_blocked:
        return NextNode.SAFETY_REVIEW
    if state.requires_user_input:
        return NextNode.ASK_USER
    if state.success_criteria_met:
        return NextNode.SYNTHESISE
    if state.budget.exhausted:
        return NextNode.SYNTHESISE_LIMITED
    if state.no_progress:
        return NextNode.REPLAN_OR_STOP
    if state.blocking_contradiction:
        return NextNode.REVISE_HYPOTHESES
    return NextNode.SELECT_ACTION
```

The recurrence limit remains a hard upper bound. A recurrence limit is not
itself a stopping strategy. It is the final containment mechanism after
meaningful stopping criteria have failed.

## 10. Belief and hypothesis updates

For a finite hypothesis set `H = {h_1..h_n}` the belief state is `P_t(h_i)`.
Bayesian updating after evidence `e`:

```
P_{t+1}(h_i) = P(e | h_i) P_t(h_i) / sum_j P(e | h_j) P_t(h_j)
```

Exact likelihoods will rarely be known, so three update modes are supported:

1. Exact probabilistic update, where calibrated distributions exist.
2. Empirical likelihood update, estimated from prior recorded transitions.
3. Evidence-weighted heuristic update, used during early implementation.

The heuristic operates in log-odds space:

```
l_{t+1}(h) = l_t(h) + w_e * s(e, h)
l_t(h)     = log( P_t(h) / (1 - P_t(h)) )
P_{t+1}(h) = 1 / (1 + exp(-l_{t+1}(h)))
```

where `w_e` is evidence reliability and `s(e,h)` in `[-1,1]` measures whether
evidence supports or contradicts the hypothesis.

Heuristic confidence values must be labelled as scores unless calibrated
against observed frequencies. MIMIR must not present arbitrary model confidence
as statistically meaningful probability.

## 11. Prediction residuals

Scalar: `r_t = |y_t - y_hat_t| / (sigma_t + epsilon)`.
Categorical: `r_t = -log P(y_t | S_{t-1}, a_{t-1})`.

Structured residuals decompose into: missing expected observations, unexpected
observations, incorrect entity state, incorrect causal direction, magnitude
error, temporal error, execution error.

Residuals update hypothesis confidence, evaluate prediction models, and
identify unknown system behaviour. A large residual does not automatically mean
the action failed. It may indicate the world model was wrong and the action was
highly informative.

## 12. Action selection

```
Score(a) = alpha*I(a) + beta*U(a) + gamma*N(a)
         - delta*C(a) - lambda*R(a) - mu*D(a)
```

`I` expected information gain, `U` expected progress, `N` novelty, `C` cost,
`R` risk, `D` duplication. All terms normalised to `[0,1]`. Risk is also
enforced through hard policy: a high score cannot override a prohibition.

### 12.1 Expected information gain

```
I(a) = E_{o ~ P(o|a)} [ D_KL( P(H | o,a) || P(H) ) ]
D_KL(P||Q) = sum_h P(h) log( P(h)/Q(h) )
```

The first implementation need not integrate over every possible observation.
Approximations: predicted hypothesis discrimination, unresolved questions
addressed, expected entropy reduction, historical tool usefulness for similar
states, model-estimated information value, deterministic domain rules.

### 12.2 Hypothesis entropy

```
H(H) = -sum_i P(h_i) log P(h_i)
dH(a) = H(H_t) - E_o[ H(H_{t+1} | o,a) ]
```

Entropy reduction is not the sole objective. A system could become confidently
wrong. Evidence quality and prediction calibration remain necessary.

### 12.3 Expected utility

`U(a) = sum_o P(o|a,S_t) u(o, G_t)`. For investigation: resolving a required
claim, finding a source location, reproducing a defect, disproving a dangerous
hypothesis, producing an executable patch, passing a verification requirement.

### 12.4 Cost

`C(a) = w_t*C_time + w_c*C_compute + w_k*C_tool + w_m*C_context`, measured from
telemetry where possible rather than permanently guessed.

### 12.5 Risk

Represented by the existing deterministic R0-R4 policy.

```
Eligible(a) = CapabilityAllowed(a) and PolicyAllowed(a) and BudgetAvailable(a)
```

An ineligible action receives no score because it is not a candidate.

## 13. Progress measurement

Normalised components: `E` useful new evidence, `H` meaningful hypothesis
change, `Q` questions resolved, `W` world-model state change, `V` verification
progress, `X` successful experiment, `D` duplication penalty, `K` unresolved
contradiction introduced.

```python
progress = (
    0.25 * evidence_gain
    + 0.20 * hypothesis_change
    + 0.15 * questions_resolved
    + 0.15 * world_state_change
    + 0.15 * verification_gain
    + 0.10 * experiment_gain
    - 0.20 * duplication
)
```

These weights are initial policy, not mathematical truth. They must be
evaluated and adjusted through controlled experiments.

## 14. No-progress detection

Track a progress window `P_bar_t = (1/k) sum_{i=t-k+1}^{t} Progress_i`.
No-progress may be declared when `P_bar_t < tau_P` **and** all of: no critical
new evidence, no material hypothesis update, no unresolved action with high
expected information gain, no pending deterministic verification, no newly
identified safe capability, repeated-action similarity above threshold.

A patience parameter `k` prevents stopping after one inconclusive but
legitimate action. Initial values conservative, for example `k = 2`. `tau_P`
must be derived from evaluation data rather than invented permanently here.

## 15. Stopping conditions

- **SUCCESS** - required output claims meet their evidence threshold
  (`Coverage_required >= tau_C`) and `Contradictions_blocking = 0`.
- **NO_PROGRESS** - progress window below threshold and no candidate action has
  sufficient expected value.
- **BUDGET_EXHAUSTED** - tool calls, model calls, context size, elapsed time,
  recurrence, compute or monetary budget.
- **NEEDS_USER** - material ambiguity not safely resolvable from evidence.
- **POLICY_BLOCKED** - next useful action prohibited or requires approval.
- **INSUFFICIENT_EVIDENCE** - available evidence cannot support a reliable
  conclusion and no remaining safe action is likely to change that.
- **INTERNAL_FAILURE** - a required subsystem failed with no safe fallback.
  MIMIR must preserve partial evidence and report the failure honestly.

## 16. Object-centric world model

Entity types: Repository, Package, Module, Class, Function, Endpoint, Service,
Deployment, Pod, Cluster, Database, Table, Queue, Topic, Configuration, Metric,
LogPattern, Alert, Incident, PullRequest, Commit, Test, Owner.

Relations: CONTAINS, CALLS, DEPENDS_ON, READS_FROM, WRITES_TO, QUERIES,
DEPLOYS, RUNS_IMAGE, CONFIGURES, EMITS, TRIGGERS, OBSERVED_ON, MODIFIES, TESTS,

Initially symbolic and database-backed. Must support entity resolution,
temporal state, provenance, relation confidence, evidence attachment,
stale-state invalidation, contradiction detection, impact traversal and

## 17. JEPA-inspired latent prediction

Joint-Embedding Predictive Architectures predict abstract target
representations from context rather than reconstructing raw detail. MIMIR
adopts the principle, not immediately the architecture: a transition model
should predict a compact task-relevant latent state rather than full future
logs or prose.

```
z_t          = f_theta(S_t)
z_hat_{t+1}  = g_phi(z_t, a_t)
z_{t+1}      = f_theta(S_{t+1})
L_pred       = d( z_hat_{t+1}, stopgrad(z_{t+1}) )
```

A learned world model will not be introduced until MIMIR has accumulated
sufficient reliable transition data. The initial world model remains explicit,
structured and inspectable.

## 18. Causal hypothesis model

The factual world model records observed state; the causal model represents
proposed mechanisms.

```python
@dataclass(frozen=True)
class CausalEdge:
    cause_id: str
    effect_id: str
    confidence: float
    evidence_ids: tuple[str, ...]
    counterevidence_ids: tuple[str, ...]
    intervention_ids: tuple[str, ...]
    status: CausalStatus
```

Statuses: PROPOSED, SUPPORTED, CONTRADICTED, INTERVENTION_SUPPORTED, REJECTED.
Correlation alone may support a hypothesis but may not mark it
intervention-supported.

### 18.1 Counterfactual representation

`P(Y | do(X=x), E)`. MIMIR will not initially claim to calculate fully
identified causal effects from arbitrary observational data. It supports
practical counterfactual reasoning through explicit domain rules, dependency
graphs, sandbox experiments, historical interventions, before-and-after
comparison, controlled tests and human-labelled causal patterns.

### 18.2 Causal admission rule

Promotion from SUPPORTED to INTERVENTION_SUPPORTED requires at least one of: a
controlled sandbox intervention, a reproducible test, a verified production
change with sufficient isolation, a deterministic mechanism proving the effect,
or strong historical intervention evidence.

This prevents MIMIR from turning every temporal correlation into a dramatic
root-cause declaration.

## 19. Active-inference-inspired action selection

```
G(a) = -eta*I(a) - rho*U(a) + kappa*C(a) + lambda*R(a)
```

The preferred action minimises `G(a)`, equivalently maximising the earlier
score. The architecture adopts the operational principle - select actions that
both advance preferred outcomes and reduce uncertainty - without claiming that
active inference alone constitutes intelligence.

## 20. Neuro-symbolic reasoning

LLM proposes a hypothesis; structured extraction pulls the operands; a symbolic
layer computes; an evidence critic confirms each operand against observation;
the language layer explains the verified result.

The symbolic layer supports arithmetic, Boolean constraints, graph queries,
dependency reasoning, schema validation, temporal ordering, policy rules,
configuration comparison and simple constraint satisfaction. Mature external
solvers may be integrated rather than reimplemented.

## 21. Graph reasoning

Explicit graph algorithms for reachability, dependency impact, shortest causal
or call paths, strongly connected components, cycle detection, ownership
traversal, topology comparison, change impact, dominator analysis and
call-graph exploration.

The LLM may determine which operation is semantically relevant; the graph
engine executes it exactly. A neural algorithmic reasoner may assist routing or
prediction, but deterministic algorithms remain authoritative wherever an exact
implementation exists.

## 22. Statistical and temporal reasoning

Trend estimation, anomaly detection, correlation analysis, change-point
detection, distribution comparison, confidence intervals, baseline modelling,
time-series forecasting. The LLM explains results but does not perform
statistical computation through prose.

All statistical outputs must record sample size, time window, missing-data
treatment, assumptions, selected test or model, uncertainty and effect size
where relevant.

## 23. Continuous-time and event-driven models

Liquid time-constant and closed-form continuous-time models are potentially
relevant to a future continuously running MIMIR consuming metrics, logs,
deployment events, CI events, repository changes, queue state and database
signals. Not required for the initial recurrent investigator.

Considered only when MIMIR has reliable temporal datasets, a static statistical
baseline exists, the model can be evaluated prospectively, it improves
detection or efficiency, and its outputs remain observable and
non-authoritative.

## 24. Sparse event-driven activation

```
new deployment event -> update deployment and service entities
                     -> invalidate related topology state
                     -> reevaluate affected hypotheses

new repository commit -> update changed AST nodes
                      -> recompute affected call-graph region
                      -> invalidate memories linked to modified symbols

new database alert -> activate database, dependency and incident models
                   -> do not activate unrelated repository specialists
```

## 25. Memory architecture

Separate memory classes: working (the bounded workspace), semantic (durable
facts about systems), episodic (previous investigations), procedural (skills,
playbooks, workflows), failure (failed actions, misleading patterns, dead
ends), causal (supported mechanisms and intervention evidence), policy
(immutable safety and authorisation rules).

Each memory item must carry provenance, confidence or status, creation time,
verification time, validity scope, invalidation conditions, linked entities,
evidence, producer version and schema version.

## 26. Multi-index retrieval

Lexical, semantic vector, entity graph traversal, temporal, procedural skill,
prior-case similarity, causal-pattern and failure-memory retrieval.

```
R(x,q) = w_l*L + w_s*S + w_g*G + w_t*T + w_p*P + w_f*F
```

Weights initially hand-defined, later eligible AI Gene loci. Results must be
deduplicated and grouped by entity before workspace admission.

## 27. Capability routing

```
hard capability eligibility
  -> policy eligibility
  -> task-structure compatibility
  -> evidence and environment availability
  -> expected action value
  -> learned or LLM ranking only if unresolved
```

```python
@dataclass(frozen=True)
```

## 29. Critics

Operating throughout the loop, not only at synthesis: claim-support,
contradiction, progress, duplication, scope, freshness, execution, calibration
and policy.

Critics should be deterministic where practical. A learned critic must never be
the only safety barrier.

## 30. Simulation

**Code changes:** hypothesis -> candidate patch -> isolated worktree -> static
analysis -> targeted tests -> broader tests when justified -> before-and-after
comparison -> execution critic -> safety review -> human approval where
required.

**Operational reasoning:** hypothesis -> predicted metric, log or topology
pattern -> read-only query -> compare expected and observed -> update beliefs.

**Counterfactual configuration:** proposed change -> dependency analysis ->
policy checks -> sandbox or modelled effect -> risk estimate -> explicit
uncertainty.

MIMIR must clearly distinguish actual execution, sandbox execution,
deterministic simulation, learned prediction and unsupported speculation.

## 31. Synthesis

Final answers are generated from verified structured state rather than raw
transcript accumulation. The synthesiser receives the resolved goal, verified
claims, active uncertainty, evidence references, rejected hypotheses,
limitations, policy outcome and relevant artifacts.

The synthesiser must not introduce new factual claims absent from the supported
claim graph. Any unavoidable interpretation must be labelled as an inference.

## 32. Learning and transition models

From recorded transitions `(S_t, a_t, o_{t+1}, S_{t+1})`: action usefulness
prediction, no-progress prediction, tool outcome prediction, specialist
eligibility prediction, state-transition prediction, anomaly prediction,
retrieval reranking, case similarity, investigation failure prediction.

Training records must exclude or separately label corrupted runs, unverified
outcomes, model hallucinations, policy-blocked actions, user-corrected state
and stale observations.

Learned models advise the executive but do not bypass policy or evidence
verification.

## 34. Gene fitness

`F(g) = [Q, E, S, K, L, R, C]` - task success and answer quality, evidence
quality, safety, computational efficiency, latency, reproducibility,
calibration.

Safety is a hard constraint: `S(g) = S_max`. A gene violating safety is
discarded regardless of performance elsewhere.

Comparison uses Pareto dominance rather than collapsing prematurely into one
score. `g_1` dominates `g_2` when `F_i(g_1) >= F_i(g_2)` for all `i` and
`F_j(g_1) > F_j(g_2)` for at least one `j`. Metrics where lower is better must
be negated or normalised consistently. A weighted scalar may be used for
tie-breaking only after hard constraints and Pareto filtering.

## 35. Gene selection

Evaluated through a fixed deterministic corpus, replicated model runs,
provenance checks, confidence intervals, regression gates, safety gates and
resource limits.

Promoted only if: no safety regression, deterministic cases remain stable,
improvement replicates, comparison is free from material confounds, no critical
task family regresses beyond tolerance, and the candidate remains reproducible.

The Gene selects orchestration policy. It does not self-modify arbitrary source
code.

## 36. Evaluation mathematics

**Success rate** `p_hat = (1/n) sum y_i`, with uncertainty intervals. Wilson
intervals preferred over naive normal intervals for binary outcomes.

**Tool efficiency** = verified useful evidence units / normalised execution
cost, where cost combines tool calls, model tokens, latency and compute. Raw
line or evidence count must not be treated as quality.

**Evidence precision** = evidence items used in supported claims / evidence
items retrieved.

**Evidence recall** = required evidence recovered / required evidence
available.

**Calibration** - Brier score `BS = (1/n) sum (p_i - y_i)^2`, lower better;
expected calibration error `ECE = sum_b (|B_b|/n) |accuracy(B_b) -
confidence(B_b)|`. Applies only to probabilities with defined semantics;
arbitrary model self-confidence is not eligible.

**Reproducibility** = modal outcome count / replicate count, with a detailed
metric comparing final outcome, selected tools, evidence set, hypotheses,
critical claims and safety decisions.

**Progress efficiency** = `sum_t Progress_t / sum_t Cost(a_t)`. This directly
tests whether recurrence creates useful state changes rather than more
activity.

## 37. Phase plan

**Phase 0 - Preserve the foundation.** Substantially complete: run provenance,
deterministic safety, evaluation comparability, persistent evidence, typed
tools, execution telemetry. Continue: prevent regressions, expand provenance to
cognitive schemas and Gene versions.

**Phase 1 - Eliminate waste.** Deterministic specialist eligibility, action
signature deduplication, repeated-tool detection, bounded budgets, no-progress
measurement, no-progress stopping.
*Hypothesis:* failed investigations consume fewer tools without reducing
successful-case quality.
*Acceptance:* no deterministic regression; fewer repeated tool calls; lower
cost on failed cases; stable evidence recall on successful cases.

**Phase 2 - Structured cognitive state.** Entity, Relation, Observation, Claim,
Hypothesis, Prediction, Action, Outcome, Transition, bounded workspace.
*Hypothesis:* MIMIR can represent what changed between rounds without replaying
the transcript.
*Acceptance:* transitions serializable; every claim links to evidence; every
action links to a goal or hypothesis; transcript size no longer determines
durable state size.

**Phase 3 - Close the loop.** Recurrent edge, state-update node, hypothesis
revision, action generation, action ranking, progress critic, stop/continue/
replan/ask routes.
*Hypothesis:* a later action is selected because of an earlier observation
rather than a static initial plan.
*Acceptance:* at least one evaluation family requires adaptive second-round
action; successful adaptive cases outperform the single-pass baseline;
recurrence remains bounded; failed loops stop through policy rather than only
maximum rounds.

**Phase 4 - Object-centric world graph.** Canonical entity resolution, relation
store, evidence attachment, temporal validity, graph traversal, stale-state
invalidation, repository and service topology.
*Acceptance:* logs, metrics, code and infrastructure attach to shared entities;
dependency impact queries execute deterministically; stale observations are not
treated as current facts.

**Phase 5 - Causal hypotheses and prediction residuals.**
*Acceptance:* hypotheses make explicit predictions; predictions are scored
after execution; contradicted hypotheses lose confidence; causal claims
distinguish observational from intervention support.

**Phase 6 - Mixed reasoning substrate.** AST parsers, graph algorithms,
symbolic calculation, statistical analysis, configuration validators,
deterministic command constructors, constraint solvers. Each replacement
evaluated independently.

**Phase 7 - Simulation-first software engineering.** Task worktrees, candidate
patch isolation, test selection, static analysis, before-and-after comparison,
execution critics, artifact persistence.

**Phase 8 - Multi-index memory.** Lexical, vector, graph, temporal, procedural,
failure, case similarity, retrieval fusion.

**Phase 9 - Learned transition model.** Once sufficient transition data exists.
Must remain optional and replaceable.

**Phase 10 - Continuous event-driven cognition.** Only when justified. Liquid or
other continuous-time networks evaluated here, not before.

**Phase 11 - AI Gene.** Expose evaluated policy loci and use the evaluation
harness for constrained policy selection.

## 38. Immediate implementation plan

**38.1 Specialist eligibility.** Apply deterministic capability constraints
before model-based routing.

**38.2 No-progress stopping.** Measure whether actions materially change
evidence, hypotheses, unresolved questions, world state or verification status.
Stop when repeated transitions fail to create progress.

**38.3 Minimal recurrent edge.**

```
success                     -> synthesise
progress + unresolved work  -> select next action
contradiction               -> revise hypotheses
no progress                 -> replan once, then stop
missing context             -> ask user
unsafe                      -> safety review
```

Together these produce the minimum viable cognitive loop: act -> observe ->
update -> measure -> decide.

## 40. Rejected alternatives

- **Continue scaling the council.** More LLM specialists provide no persistent
  state, exact reasoning, better stopping, causal validation, lower cost or
  improved reproducibility. They increase orchestration and context complexity.
- **Replace the model with a larger one as the primary strategy.** A stronger
  model may improve individual tasks but does not solve single-pass execution,
  context growth, absent world state, absent prediction, weak stopping,
  deterministic routing failures or lack of simulation. Model upgrades remain
  permitted but are not the architecture.
- **Implement a learned world model immediately.** Insufficient clean
  transition records.
- **Implement full active inference immediately.** Exact generative models and
  outcome distributions are unavailable for much of the domain.
- **Build a general causal discovery engine immediately.** Observational
  operational data contains confounding, missing variables and inconsistent
  interventions.
- **Use neural algorithmic reasoning instead of exact algorithms** for
  authoritative paths.
- **Use one enormous vector database as memory.** Semantic similarity alone
  does not represent identity, causality, time, contradiction, validity,
  procedure or evidence strength.
- **Allow the Gene to mutate safety.** Rejected unconditionally.

## 41. Consequences

**Positive:** MIMIR can adapt after observing results; investigations become
explicit state transitions; language models become replaceable; formal tasks
become deterministic; failed predictions become learning signals; memory gains
identity, time and causality; tool calls become measurable decisions;
simulation becomes part of reasoning; continual learning becomes possible from
verified transitions; local models can perform narrower work efficiently; the
evaluation harness becomes capable of selecting orchestration policy.

**Negative:** substantially more complexity; schema design becomes critical;
entity resolution will be difficult; confidence values may mislead unless
calibrated; action-value estimates will initially be crude; causal claims
require discipline; recurrent systems introduce new failure modes; more
persistence creates migration and invalidation burdens; learned world models
require substantial clean data; debugging interactions between substrates will
be harder than debugging one pipeline.

**Mitigations:** incremental implementation, explicit schemas, deterministic
baselines, feature flags, replayable transitions, strict provenance, evaluation
before promotion, bounded recurrence, immutable policy, model-independent
fallbacks.

## 42. Invariants

1. No unapproved production mutation.
2. Safety decisions do not depend on an LLM.
3. Every tool execution has provenance.
4. Every final factual claim links to evidence.
5. Every recurrent run has hard limits.
6. Learned predictions cannot overwrite observations.
7. Model confidence is not presented as probability unless calibrated.
8. Causal claims distinguish correlation from intervention evidence.
9. Gene mutation cannot affect immutable safety loci.
10. A failed new subsystem can be disabled without losing investigation state.
11. The system can always explain why an action was selected.
12. Partial failure preserves useful evidence and state.
13. Comparisons with prior runs require compatible provenance.
14. No model is considered intelligent merely because it produces persuasive
    language.

## 43. Success criteria

The architecture is successful when MIMIR can:

- select a later action based on an earlier unexpected observation;
- stop a failing investigation before exhausting its maximum round count;
- maintain task state without replaying the complete transcript;
- represent competing hypotheses explicitly;
- predict observations before testing them;
- reduce confidence when predictions fail;
- connect code, infrastructure, logs and metrics to shared entities;
- use exact engines for formal tasks;
- verify code changes through isolated execution;
- preserve safety across model replacement;
- improve action selection from verified transition history;
- demonstrate replicated gains under the evaluation harness.

## 44. Final architectural position

MIMIR will not attempt to create intelligence by scaling a conversation. It
will create a system that maintains beliefs about a changing world, represents
objects and relationships, forms competing explanations, predicts consequences,
chooses observations and experiments deliberately, applies the correct
computational mechanism, compares expectations with reality, corrects itself,
preserves evidence, learns only from verified outcomes, and remains bounded by
deterministic safety.

> The LLM provides language, abstraction and creative proposals.
> MIMIR provides state, memory, prediction, causality, experimentation,
> verification, policy and control.

The intelligence is not expected to reside in one algorithm. It is expected to
emerge operationally from the disciplined interaction of perception, structured
state, predictive models, causal hypotheses, active information gathering,
symbolic and algorithmic reasoning, execution, verification, memory and
correction.

The immediate objective is not to claim general intelligence. It is to build
the smallest system that can predict, act, observe, detect that it was wrong,
update itself, and choose a better next action.

Everything beyond that depends on making this loop real, measurable and safe.
